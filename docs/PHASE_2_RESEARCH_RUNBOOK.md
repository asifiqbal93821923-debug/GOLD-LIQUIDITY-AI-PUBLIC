# Phase 2 research runbook

This runbook describes how to produce **real evidence** for Phase 2. The workflow does not fabricate history or infer feed identity from the filename.

## 1. Prepare one provider's closed candles

In TradingView, open the exact XAUUSD ticker used by the Pine script. Export chart data separately for 4H, 1H and 15M from the same chart provider and ticker. Optional 5M may be included. TradingView's Export chart data can include OHLC and numeric plots generated by the script.

Put the files in data/phase2 using these exact names:

- xauusd_4h.csv
- xauusd_1h.csv
- xauusd_15m.csv
- xauusd_5m.csv (optional)
- pine_reference_1h.csv (optional; see step 2)

Required candle columns: time,open,high,low,close. Volume is optional. Timestamps must be UTC Unix seconds/milliseconds or timezone-aware ISO-8601 strings. Export fully closed bars only. Do not mix OANDA:XAUUSD, TVC:GOLD, COMEX futures, broker MT5, or other sources. They are not interchangeable data feeds.

Aim for aligned overlapping history of approximately at least 250 x 4H bars, 1,000 x 1H bars and 4,000 x 15M bars over the same calendar interval. The importer computes the actual 60/20/20 partitions and requires at least 50 fully closed bars in every required timeframe in each partition; it refuses the dataset otherwise. More history spanning multiple volatility regimes is preferred. Do not exceed 6,000 1H bars for one MTF replay input. These are technical floors, not statistically sufficient sample sizes.

## 2. Pine reference event export

For the Alpha Signal Engine Pro Pine source that this repository ports, add a numeric plot of its actual confirmed signal series, using the existing Pine boolean variables in that source. Example mapping (adapt variable names; do not paste blindly):

    plot(buyCondition ? 1 : sellCondition ? -1 : 0, "phase2_signal", display=display.data_window)

Export chart data again and save the file as data/phase2/pine_reference_1h.csv. Keep the plot header phase2_signal. Values map to 1=BUY, -1=SELL, 0=WAIT.

Also add data/phase2/alpha-settings.json if the Pine engine inputs differ from the Python defaults. It must be a JSON object with the exact exposed Alpha input names and values. Without the exact source code and inputs, a parity percentage would be meaningless. This Alpha port is not the user's separate PRO XAU V2.0 strategy or a different SMC indicator.

## 3. Supply broker execution costs

In the workflow inputs, use the target account's observed XAUUSD spread points, conservative slippage points, commission converted to price points per side, and the actual price point size from that broker's contract specification. Do not use the example values from old documentation as assumed real costs. The workflow requires all four cost parameters explicitly.

## 4. Run the GitHub Action

Open the repository's Actions tab, choose "Phase 2 same-feed research", click "Run workflow", and enter the exact provider name, exact ticker, and cost assumptions. The action reads the files above and generates:

- validated MTF dataset + feed manifest
- Alpha optimizer report with its selected candidate and single sealed test
- 1H Entry/SL/TP calibration report and one sealed test
- costed 70/30 walk-forward/OOS report
- separate false-breakout, liquidity-sweep and retest event/outcome report
- Python 1H signal CSV and optional Pine/Python event parity report

Download the workflow artifact after the run completes. A workflow that stops at the CSV gate, data-quality gate or an insufficient-history message has not completed empirical Phase 2.

## 5. Forward paper trading

The offline paper ledger in scripts/paper_trade_ledger.py can process one new fully closed candle and one decision at a time. It is not a continuously hosted webhook receiver, does not retain a live connection, and never sends broker orders. A real forward test requires a persistent feed/receiver on a reachable host, duplicate-event protection, broker-matched quotes/costs, durable ledger storage, and a predeclared observation length. It must run through actual future market sessions; a historical replay cannot substitute for this step.

## Research caveats

- The price-action classifier uses OHLC proxies only. It cannot observe real order-book depth, MBO, bank pending orders or verified institutional identity.
- A same-feed event match establishes signal parity only for the tested timestamps and settings; it does not establish profitability.
- Spread/slippage/commission inputs materially affect results. Report every assumption with the output.
- Keep the sealed test untouched after it is evaluated. Do not select another candidate based on sealed-test results.
